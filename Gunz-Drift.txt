### Patch: Extended `.gunzstats` for Drift (no backward compatibility)

This patch modifies the following sections of GUNZ 3.65.0:

- §4.8 – replace entirely with the mandatory 32‑byte format.
- §4.9 – replace entirely with the extended compression scheme.
- §4.6 – add `drift_enabled` metadata field.
- §4.3 – note that `stats_fingerprint` covers the extended file.
- §6 – add optional drift support under Runtime.

All other sections remain unchanged.

---

#### 1.  §4.8 — Raw Statistics Companion File (`.gunzstats`)

**Replace** the existing §4.8 with:

> **§4.8 Raw Statistics Companion File (`.gunzstats`)**
> 
> The runtime may emit a raw statistics file for any scan.  When `long_term_scan` is active, emitting the file is strongly recommended.  When drift computation is enabled (as defined by the GUNZ‑DRIFT companion extension), the file **shall** be emitted, regardless of scan mode.
> 
> All `.gunzstats` files use the same 32‑byte record format.  The magic number is `0x475A4C01` (little‑endian).  No other magic number is valid; a conformant decoder shall reject any `.gunzstats` file whose magic is not `0x475A4C01` with `GUNZ_MALFORMED_BYTECODE`.
> 
> **Format** – packed 32‑byte records, one per candidate, in map order:
> 
> | Offset | Size | Field | Description |
> |--------|------|-------|-------------|
> | 0  | u32 | `block_count` | Number of temporal blocks evaluated. |
> | 4  | u64 | `sum_block_time` | Sum of block times (base time units). |
> | 12 | u64 | `sum_block_time_sq` | Sum of squared block times. |
> | 20 | u16 | `count_adv_lo` | Number of short advances. |
> | 22 | u16 | `count_adv_hi` | Number of long advances. |
> | 24 | s16 | `drift` | Intra‑block drift (ticks × 100 per cycle).  Zero if drift is not enabled or `N < 2`. |
> | 26 | s16 | `peak_drift` | Peak absolute drift observed across the measurement window, with original sign (ticks × 100 per cycle). |
> | 28 | u32 | `reserved` | Must be zero.  Readers shall reject any file where this field is non‑zero with `GUNZ_MALFORMED_BYTECODE`. |
> 
> All time values are in the base time unit.  The number of records equals the total number of candidates evaluated.
> 
> When drift is not enabled, the `drift` and `peak_drift` fields shall be written as zero, but the file still uses the 32‑byte record format and magic `0x475A4C01`.  This uniformity simplifies decoders and avoids format‑detection logic.

---

#### 2.  §4.9 — Compressed Statistics File (`.gunzstatz`)

**Replace** the existing §4.9 with:

> **§4.9 Compressed Statistics File (`.gunzstatz`)**
> 
> Optional compressed version of `.gunzstats` using delta encoding with run‑length and LEB128.  The file uses the same 32‑byte record structure as the uncompressed file.
> 
> **File structure:**
> 
> | Offset | Size | Field |
> |--------|------|-------|
> | 0  | u32 | `magic` `0x475A4C01` |
> | 4  | u32 | `candidate_count` |
> | 8  | u32 | `anchor_freq_raw` |
> | 12 | 32 bytes | `anchor_record` (first candidate’s statistics, all 32 bytes) |
> | 44 | … | compressed delta stream |
> 
> **Compression algorithm:** For each subsequent candidate, compute signed deltas of the seven fields (`block_count`, `sum_block_time`, `sum_block_time_sq`, `count_adv_lo`, `count_adv_hi`, `drift`, `peak_drift`).  If all deltas are zero, emit byte `0x00` followed by the run length encoded as **unsigned LEB128**.  Otherwise emit a bitmask byte (bits 0‑6 for the seven fields in order) and for each set bit, emit the signed delta encoded as **signed LEB128**.  Bit 7 of the bitmask is reserved and must be zero; if set, the decoder shall reject the file with `GUNZ_MALFORMED_BYTECODE`.
> 
> The 4‑byte `reserved` field (offsets 28‑31 of each decompressed record) is **not** delta‑compressed; it is always expected to be zero.  Decoders shall verify that this field is zero after decompression and reject the file with `GUNZ_MALFORMED_BYTECODE` if it is non‑zero.
> 
> | Bit | Field |
> |-----|-------|
> | 0 | `block_count` |
> | 1 | `sum_block_time` |
> | 2 | `sum_block_time_sq` |
> | 3 | `count_adv_lo` |
> | 4 | `count_adv_hi` |
> | 5 | `drift` |
> | 6 | `peak_drift` |
> | 7 | (reserved) |
> 
> **LEB128 encoding (normative – Full profile only):**  
> *(Unchanged from the existing specification.)*

---

#### 3.  §4.6 — Map Companion Metadata File (`.gunzmeta`)

In the table of mandatory keys, **add** the following row after `long_term_scan`:

> | `drift_enabled` | boolean | (Optional) `true` if the drift metric was computed for this scan.  Absent or `false` otherwise. |

*(`stats_fingerprint` already covers the file; no change needed.)*

---

#### 4.  §4.3 — Integrity & Fingerprint

In the paragraph discussing `stats_fingerprint`, **add** the following sentence at the end:

> When the extended 32‑byte `.gunzstats` format (magic `0x475A4C01`) is used, the fingerprint covers that file, including the drift fields.

---

#### 5.  §6 — Conformance

In the **Runtime** subsection, **add** the following bullet after the existing `.gunzstats`/`.gunzstatz` item:

> – Support the `.gunzstats` 32‑byte record format with magic `0x475A4C01`.  Reject any `.gunzstats` file with a different magic.  Drift field computation is optional; implementations that do not support drift shall write zero in those fields.

---

This patch integrates drift into the core specification with no backward‑compatibility baggage.  The map entry and map version remain unchanged.

## 1. GUNZ‑DRIFT Draft 0.9a (cleaned)

**GUNZ‑DRIFT — Intra‑Block Advance Trend Metric Extension**  
*Draft 0.9a — Companion to GUNZ 3.65.0*

*[Sections 1–4, 5.2, 5.3, 6–9 are identical to draft 0.9.  Only the sections that contained backward‑compatibility clauses are updated.  The full draft is reproduced below for completeness.]*

---

### 5.1 Drift in the Extended `.gunzstats` File

Drift values are stored in the extended `.gunzstats` file defined by GUNZ 3.65.0 §4.8.  The format uses **32‑byte records** with the following layout:

| Offset | Size | Field | Description |
|--------|------|-------|-------------|
| 0  | u32 | `block_count` | Number of temporal blocks evaluated. |
| 4  | u64 | `sum_block_time` | Sum of block times (base time units). |
| 12 | u64 | `sum_block_time_sq` | Sum of squared block times. |
| 20 | u16 | `count_adv_lo` | Number of short advances. |
| 22 | u16 | `count_adv_hi` | Number of long advances. |
| 24 | s16 | `drift` | Intra‑block drift (ticks × 100 per cycle).  Zero if drift computation is not enabled or `N < 2`. |
| 26 | s16 | `peak_drift` | Peak absolute drift observed across the measurement window, with original sign (ticks × 100 per cycle). |
| 28 | u32 | `reserved` | Must be zero.  Reserved for future use. |

All time values are in the base time unit.  The number of records equals the total number of candidates evaluated.

The first four bytes of the file shall be the magic number `0x475A4C01` (little‑endian).  This is the **only** valid magic for `.gunzstats` files.  A conformant implementation shall reject any `.gunzstats` file with a different magic number, returning `GUNZ_MALFORMED_BYTECODE`.

The `.gunzstats` file is emitted for any scan mode when drift computation is requested, not only when `long_term_scan` is active.  For single‑block scans, the `block_count` field is `1`, and the `drift` and `peak_drift` fields contain the single‑block drift value.

---

### 8. Conformance

A conformant GUNZ‑DRIFT implementation must:

- Compute drift using the exact least‑squares formula defined in §2, with 256‑bit intermediates for `sum_a`, `sum_ia`, `num`, and `den`.
- Use a 128‑bit signed accumulator for the long‑term mode sum (§4).
- Apply half‑to‑even rounding to the final division, using the signed rounding convention specified in §2.
- Produce the per‑cycle advance sequence using the placement algorithm of §2.1, with the initial error `E` derived from `rem = (N * T) % quantum` as specified, using the unrounded continuous block time `P = N * T`.
- Saturate the drift result to a signed 16‑bit integer before storage.
- Produce bit‑identical drift values for identical inputs.
- Emit the `.gunzstats` file with magic `0x475A4C01` and 32‑byte records when drift is computed, for any scan mode.
- Reject any `.gunzstats` file whose magic is not `0x475A4C01` with `GUNZ_MALFORMED_BYTECODE`.
- Record `drift_enabled = true` in `.gunzmeta`.
- Compute peak drift as the drift value with the largest absolute magnitude among blocks, preserving its original sign, with a positive‑sign tie‑break.
- If producing compressed `.gunzstatz`, use bit 5 for `drift` delta and bit 6 for `peak_drift` delta; reject any file with reserved bit 7 set.

Support for GUNZ‑DRIFT is **optional** for GUNZ 3.65.0 conformance.  Implementations that do not support the drift extension shall reject `.gunzstats` files entirely (magic `0x475A4C01`).  Standard 16‑byte map entries are used; no custom map version is emitted.
