# GUNZ 5.0.0 — Performance Implementation Guide (Informative)

*How to build a high‑performance, conformant GUNZ dense scanner — safely and deterministically.*

---

## 1. Why performance matters

A typical AI‑driven tuning session may evaluate millions of frequency candidates across multiple zones and time‑unit scales. The core evaluator is the hot path; every microsecond saved there translates directly into faster feedback loops, lower energy consumption, and more responsive autonomous systems.

The techniques described in this guide can accelerate the dense scanner by **10–500×** while remaining **bit‑identical** to a naïve implementation. No approximations, no guesswork — only intelligent exploitation of the evaluator’s deterministic structure.

---

## 2. Fundamental rule

> **Any optimisation that changes a single bit of the output map is non‑conformant.**  
> The GUNZ resonance evaluator is a pure function. Its output is fully determined by the input parameters and the dense‑scan frequency grid. The goal is to compute that exact output with less work, not to compute something “close enough.”

---

## 3. What’s changed in 5.0.0 — impact on performance

GUNZ 5.0.0 is a major revision. The core arithmetic is still integer‑only, but many structural changes affect what an implementation must optimise.

| Change | Impact on performance |
|--------|-----------------------|
| **Three independent metrics replace scalar score** | No combined ranking score. Each metric (`block_time_inaccuracy`, `jitter`, `advance_regularity`) is computed and saturated separately. No score loop. |
| **Mandatory closed‑form advance regularity** | Advance regularity is always computed from two values using a closed form. No per‑cycle accumulation for advance regularity. This is both faster and safer. |
| **64‑byte map header** | Header stores all evaluator inputs: `effective_step`, `window_duration`, `evaluated_candidate_count`, etc. No `step_freq_overflow` or extension. |
| **`effective_step` is a direct `u32`** | No `step_freq` u16/overflow split. Resolved step size is stored directly. |
| **Physical stability width** | Stability width is based on central total time and `stability_tolerance_time`, not a score valley. This changes Phase 2 geometry but not Phase 1 hot loop. |
| **`FLAG_INVALID`, `FLAG_CENTRAL_ABOVE`, `FLAG_CENTRAL_BELOW`** | New flags add per‑candidate classification. They must be computed and stored. |
| **Long‑jump type tags** | `freq_delta_start` is a type tag on long‑jump entries: 0 = unevaluated gap, 1 = sparse‑omitted perfect interval. This affects sparse emission. |
| **`window_duration` up to `2^64−1`** | Long‑term mode may have extremely large windows. Efficient grouping of identical blocks becomes essential. |
| **Fixed Safe Profile caps** | Caps define safe arithmetic ranges. This guides when narrower integer types may be used with proof. |
| **Reference source semantics** | `reference_block_time == 0` iff `reference_source == 0`. Guessing rule tries midpoint, then `freq_low`, then `freq_high`. Off hot path. |
| **Attestation rules** | Required when `callback_sandboxed == true`, Full profile claimed, and at least one callback (`PURE_CALL` or `STREAM`) was invoked. No effect on evaluator performance. |

All plateau‑jump and cache‑filling techniques described below are fully conformant with GUNZ 5.0.0 **under the stated preconditions**.

## 4. The jitter window radius

The jitter window radius `R` is derived from the map header’s `jitter_window_radius` field (byte 30) or from the library profile.

- If the stored value is `0`, the default radius **10000** (21 points, ±0.1 Hz) is used.
- If the stored value is non‑zero, the actual radius in 10⁻⁵ Hz units is **`stored_value × 1000`**.

The jitter offsets Δ are generated as `-R, -R+1000, -R+2000, …, +R`. All offsets are multiples of 1000 (in 10⁻⁵ Hz units). The maximum number of jitter points is **511** (when `jitter_window_radius = 255`).

When a candidate is near `freq = 1`, some offsets would be non‑positive; those points are silently skipped and the effective window shrinks. The standard‑deviation computation must use the actual number of valid points.

**Important:** For plateau‑jump edge zones, we do **not** compute a candidate count by dividing `R` by `effective_step`. Edge zones are defined **directly in frequency** as explained in §5.1. This avoids any divisibility or truncation issues.

### 5.1 Window‑aware plateau‑jump — skip only when the entire jitter window is safe

#### Why it works

The cycle time `T` is a discrete step function of frequency: `T = floor(C / freq)`. When `T` is constant over a frequency interval, and the entire jitter window of every candidate in that interval lies inside that interval, then **all Phase 1 metrics are identical** for every such candidate. This is because all derived quantities (`d_lo_cont`, `adv_lo_cont`, `N`, `N_hi`, `R`, `block_time`, `total_time`, and any drift values) are functions of `T` and the fixed system parameters, and `T` is constant.

This insight supersedes the earlier `N`/`N_hi`‑only plateau concept. It automatically handles nonzero `hold_cycles` and `sep_cycles`, because `total_time` includes `(hold + sep) × T`, and that term is constant when `T` is constant.

#### How to implement

1. **Enumerate T‑plateaus:** A T‑plateau is a maximal interval `[S, E]` over which `T = floor(C / f)` is constant. The boundaries are:

   ```text
   S = floor(C / (k + 1)) + 1
   E = floor(C / k)
   ```

   where `k = floor(C / f)` for any `f` in the plateau.

2. **For each T‑plateau**, compute the **jitter‑safe interior**:

   ```text
   interior_low  = S + R
   interior_high = E − R
   ```

   If `interior_low > interior_high`, the interior is empty and no replication is possible for this plateau.

3. **Grid‑align the interior** to the global scan grid:

   ```text
   grid_start = ceil_to_grid(interior_low, base_freq, effective_step)
   grid_end   = floor_to_grid(interior_high, base_freq, effective_step)
   ```

   If `grid_start > grid_end`, the interior is empty on the scan grid.

4. **Classify candidates:**

   - Candidates in `[grid_start, grid_end]` are **interior** and may be replicated from a single representative.
   - All other grid candidates in the plateau are **edge candidates** and must be evaluated individually.

5. **Emitting edge and interior candidates** requires careful handling to avoid duplicates and gaps. The definitive algorithm is given in §5.1.2.

#### Important preconditions

- The plateau‑jump optimisation **SHALL NOT** be applied to zones with an attached `PURE_CALL` unless the implementation can prove that the callback’s return value is constant across the entire plateau.
- The T‑plateau boundary enumeration must include **all** transitions of `T`. Since `T = floor(C / f)`, these are the frequencies where `floor(C / f)` changes. No separate `N_hi` transition enumeration is required for plateau‑jump because `N_hi` changes only when `T` changes or when `round(N × T / quantum)` changes, and the latter is already captured by the T‑plateau partition when the N‑search is deterministic.
- For GUNZ‑DRIFT, no additional condition is needed: if the entire jitter window is inside a T‑plateau, `T` is identical for every jitter offset, so `rem`, `E`, and drift are identical.

#### 5.1.1 Stability‑width replication within plateaus

Within a T‑plateau interior, all candidates share the same central total time `total_time` and the same `N`/`N_hi`. Therefore, Phase 2 stability‑width computations yield identical results for every candidate in the interior, provided no hard boundary (`FLAG_INVALID`, `FLAG_SKIPPED`, or long‑jump) splits the plateau. Implementations may run‑length encode the reconstructed candidate array by central total time and compute stability width once per segment instead of per candidate, reducing Phase 2 work.

#### 5.1.2 Definitive T‑plateau detection and emission algorithm

The following algorithm enumerates all T‑plateaus and emits edge and interior candidates exactly once, preserving grid alignment and handling the `T = 0` plateau.

```text
PLATEAU_DETECT(freq_low, freq_high, effective_step, base_freq, R, C):

    plateaus = []          # (grid_start, grid_end, representative)
    edge_candidates = []   # individual candidates
    f = freq_low

    while f <= freq_high:
        k = floor(C / f)

        if k == 0:
            # T = 0 plateau: from f to freq_high, all candidates invalid
            S = f
            E = freq_high
        else:
            S = floor(C / (k + 1)) + 1
            E = floor(C / k)

        S = max(S, freq_low)
        E = min(E, freq_high)

        plat_end = floor_to_grid(E, base_freq, effective_step)

        interior_low  = S + R
        interior_high = E - R

        interior_start = ceil_to_grid(interior_low, base_freq, effective_step)
        interior_end   = floor_to_grid(interior_high, base_freq, effective_step)

        # Clamp interior to actual plateau grid bounds
        interior_start = max(interior_start, f)
        interior_end   = min(interior_end, plat_end)

        # Left edge candidates
        left_end = min(plat_end, interior_start - effective_step)
        if f <= left_end:
            for g in f .. left_end step effective_step:
                edge_candidates.append(g)

        # Interior plateau
        if interior_start <= interior_end:
            plateaus.append((interior_start, interior_end, interior_start))
            right_start = interior_end + effective_step
        else:
            right_start = interior_start  # empty interior

        # Right edge candidates
        if right_start <= plat_end:
            for g in right_start .. plat_end step effective_step:
                edge_candidates.append(g)

        # Advance to next grid frequency after E
        offset = E + 1 - base_freq
        next_f = base_freq + ((offset + effective_step - 1) // effective_step) * effective_step
        f = next_f

    return plateaus, edge_candidates
```

Helper functions:

```text
ceil_to_grid(x, base, step):
    offset = x - base
    if offset % step != 0:
        offset += step - (offset % step)
    return base + offset

floor_to_grid(x, base, step):
    offset = x - base
    offset -= offset % step
    return base + offset
```

This algorithm guarantees:

- Every grid-aligned candidate is emitted exactly once.
- No candidate is evaluated using the wrong `T`.
- The reconstructed array is complete and bit-identical to a full scan.
- The `T = 0` region is handled without division by zero.

**Evaluation and replication:**

1. Evaluate all `edge_candidates` individually.
2. For each plateau in `plateaus`, evaluate the representative (`grid_start`) once, then replicate its result for every grid candidate from `grid_start` to `grid_end`.
3. Sort the combined results by frequency.
4. Reconstruct the full candidate array before Phase 2.

### 5.2 Per‑frequency block‑data cache + sliding‑window jitter

The cache‑based shortcut precomputes `total_time` and advance values for each distinct frequency. Because T‑plateaus are contiguous regions of constant `T`, the cache can be filled plateau‑by‑plateau by evaluating the representative frequency once and filling the plateau’s range with constant values. This requires that `total_time` be constant across the plateau, which is guaranteed by the T‑plateau definition.

**Cache range:** `max(1, freq_low − R)` through `freq_high + R`, at resolution 1 (every integer frequency). This ensures jitter lookups never access invalid indices.

**Memory:** For a 100 Hz zone at resolution 1, the cache covers ~10 million frequencies. With 8‑byte values, memory use is 80–120 MB, acceptable for modern hardware.

---

### 5.3 Closed‑form advance regularity (mandatory in 5.0.0)

Advance regularity is computed using the two‑valued closed form:

```text
a = 100 × adv_lo_cont
b = 100 × adv_hi_cont
n_a = N_lo,  n_b = N_hi
V = n_a × n_b × (a − b)²
D = n²
```

All products use 256‑bit unsigned arithmetic. The variance is then passed through the exact rational standard‑deviation steps (§4.5.3). This is mandatory; the general `S`/`S2` accumulation SHALL NOT be used for advance regularity.

---

### 5.4 Grouped long‑term block accumulation

When no drift companion is active, all temporal blocks at a given jitter offset are identical. The implementation may group them by accumulating weighted sums:

```text
S  = Σ m_j × total_time_j
S2 = Σ m_j × total_time_j²
n  = Σ m_j
```

where `m_j` is the number of blocks at jitter offset `j`.

The central total time `total_time_lt` is computed only at jitter offset Δ = 0. It is the single per‑candidate central value. In the absence of drift, all blocks at Δ = 0 are identical, so `total_time_lt` collapses to the single block `total_time` evaluated at Δ = 0.

This grouping is invalid if GUNZ‑DRIFT is active and the drift model introduces block‑to‑block variation.

---

### 5.5 SIMD vectorisation of the jitter window

The jitter‑window standard deviation can be vectorised with integer SIMD. Since all arithmetic is exact, the reduction order does not matter. Load multiple block times and accumulate sums/sums‑of‑squares in wide registers.

---

### 5.6 Narrow integer arithmetic (64‑bit paths) with proof

If static analysis proves all intermediate values fit in 64 bits for the actual parameters, native 64‑bit operations may be used. This is safe only with a formal proof; the Fixed Safe Profile caps provide a conservative starting point. The standard‑deviation accumulators still require 256‑bit arithmetic for jitter.

---

### 5.7 Advanced microarchitectural optimisations

The following hardware‑level techniques are allowed but must preserve bit‑identity:

1. **Bitmask batch sparse emission:** Mark 64 omitted candidates per mask word, then apply the mandatory overflow/flush logic once.
2. **Barrett reduction** for invariant divisors, with correction.
3. **Circular accumulator buffers** to reduce store‑to‑load stalls.
4. **Transposed SoA** layout.

All remain bound by the absolute bit‑identity requirement.

---

## 6. What **not** to do — the anti‑optimisations

The following shortcuts are tempting but produce **non‑conformant** maps:

1. Re‑using the candidate’s total time for all jitter points.
2. Linear interpolation of block times.
3. Reducing the jitter window size.
4. Using floating‑point arithmetic.
5. Omitting any `T` transition points in plateau enumeration.
6. Treating `effective_step == 0` as valid.
7. Omitting `effective_step` or `window_duration` from the fingerprint.
8. Hard‑coding a `MAX_STATIC_EVALUATORS` value below the implementation’s capability.
9. Confusing `reference_source` values.
10. Using the general `S`/`S2` accumulation for advance regularity.
11. Applying plateau‑jump to zones with `PURE_CALL` unless callback return is provably constant.
12. Defining edge zones by candidate count instead of frequency.
13. Forgetting to write `effective_step` in the map header.
14. Writing zero thresholds in the map header.
15. Using `long_term_scan` as a per‑entry flag.
16. Emitting statistics with incorrect record size or magic.
17. Using raw block‑time sums for jitter when total block times are required.

## 7. Algorithmic foundations — why the plateau‑jump is correct

### 7.1 The constant‑metric interval definition

A candidate frequency belongs to a **constant‑metric interval** if, when the candidate is shifted by any jitter offset Δ in the window, all resulting frequencies produce identical values for every Phase 1 metric and the central‑direction flags. This is equivalent to the entire jitter window lying inside a single T‑plateau.

When GUNZ‑DRIFT is active, the T‑plateau condition also guarantees identical drift values, because `T` is identical for every jitter offset, which fixes `rem`, `E`, and the Bresenham placement.

### 7.2 Why the full dense scan is the reference

The plateau‑jump optimisation is valid only if it produces the same consolidated map as exhaustive per‑candidate evaluation. The T‑plateau definition satisfies this because it is based on the fundamental step function `T = floor(C / f)`.

### 7.3 Enumerating plateaus exactly

The T‑plateau boundaries are computed directly from `C` and `k`. No floating‑point is required. All transition frequencies are obtained by solving `floor(C / f) = k`.

---

## 8. Putting it all together — the final scan pipeline

1. **Plan construction:** Compute T‑plateau boundaries for each zone, perform static range analysis, validate grid alignment and disjointness.
2. **Phase 1 — Build the full‑resolution block‑data cache:** For each T‑plateau, simulate one representative and fill the cache segment. Handle low‑frequency invalid jitter points.
3. **Phase 1 — Candidate evaluation:** Use the T‑plateau algorithm to classify edge and interior candidates. Evaluate edges individually, replicate interiors. Reconstruct the complete evaluated candidate array before Phase 2.
4. **Phase 2 — Stability width:** Run on the reconstructed array. May use plateau replication if no hard boundary splits the plateau.
5. **Phase 3 — Map emission:** Apply run‑length consolidation, long‑jump splitting, sparse emission, checksum, and fingerprint.

## 10. Common pitfalls and how to avoid them

| Pitfall | Fix |
|---------|-----|
| Missing `T` transitions in plateau enumeration | Enumerate all `floor(C / f)` boundaries, including `k = 0`. |
| Using the general `S`/`S2` accumulation for advance regularity | Use the mandatory closed form. |
| Assuming `FLAG_SKIPPED` must be set on long‑jumps | The sentinel alone identifies a long‑jump; `freq_delta_start` is the type tag. |
| Hard‑coding `MAX_STATIC_EVALUATORS` to 65,536 | Support at least 65,536; allow more. |
| Using floating‑point for `T` or any metric | All arithmetic must be integer. |
| Forgetting to handle invalid jitter indices near `freq = 1` | Skip points where `freq + Δ ≤ 0`. |
| Treating `reference_source = 3` as guessed | 3 is calibrated, 2 is guessed, 0 is not applicable. |
| Missing small‑plateau edge case | If no interior candidate exists, evaluate all candidates step‑by‑step. |
| Defining edge zones by candidate count instead of frequency | Use `S+R` and `E−R`; avoid division by `effective_step`. |
| Applying plateau‑jump on zones with `PURE_CALL` | Disable unless the callback return value is provably constant. |
| Assuming `effective_step` can be 0 | `effective_step` must be ≥ 1. `SCAN_RES` operand 0 defaults to 1. |
| Forgetting to write `effective_step` in the 64‑byte header | It is at bytes 40–43. |
| Omitting `effective_step` from the fingerprint | The fingerprint includes `effective_step` and `window_duration`. |
| Not validating that zones are strictly disjoint and grid‑aligned | Reject bytecode with any overlapping or misaligned `ZONE`/`SKIP_ZONE`. |
| Writing zero thresholds in the map header | Detrimental thresholds must be non‑zero in the stored header. |
| Using `long_term_scan` as a per‑entry flag | It is a header‑only field (byte 39). |
| Emitting statistics with incorrect record size or magic | Use 96‑byte records with `0x475A4C04` (raw) or `0x475A4C05` (compressed). |
| Using the raw block‑time sums for jitter in analysis | For long‑term jitter, the evaluator uses total block times (raw + hold/sep). The `.gunzstats` stores both raw and total sums. |
